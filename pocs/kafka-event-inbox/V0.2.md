# PoC V0.2 — HTTP ingestion, application port, bounded retries

**Status:** implemented in source; local execution and PostgreSQL integration validation pending.

## Run locally

```bash
git switch feat/platform-engineering-sre-handbook
git pull --ff-only
cd pocs/kafka-event-inbox
source .venv/bin/activate
inbox init
export INBOX_WEBHOOK_SECRET='replace-with-a-long-random-local-secret'
inbox serve
```

In a second terminal, from the same directory:

```bash
source .venv/bin/activate
export INBOX_WEBHOOK_SECRET='replace-with-a-long-random-local-secret'
python scripts/send_event.py http-demo-1 push
python scripts/send_event.py http-demo-1 push
inbox run-worker --count 1
inbox summary
inbox dead
```

Expected: first HTTP request returns 202 with `added:true`, second 200 with `added:false`; worker processes once. Existing pending events may be processed first: use `inbox run-worker --delivery-id http-demo-1` to isolate.

Tests cover fake repository application use case, signed HTTP requests and duplicate responses, PostgreSQL concurrent-worker locking, and bounded poison-message retries.

## Architecture choices

- **System topology:** local modular monolith; no Kafka, no microservices.
- **Application boundary:** `IngestEvent` depends on `EventRepository` Protocol; HTTP depends on use case, Postgres implements the port. The CLI remains a legacy direct adapter to support V0.1 exercises.
- **Security:** raw-body HMAC-SHA256 via `X-Inbox-Signature: sha256=<hex>`; signature comparison is constant-time. This is a custom local PoC protocol, **not GitHub's webhook format or a production auth system**.
- **Worker:** `run-worker` uses transactional processing, bounded retry and dead-letter state for invalid domain data. It is an **on-demand command**, not a background daemon. The earlier `work` command remains available for injected rollback demonstrations.
- **Concurrency:** row locks with `SKIP LOCKED`; a transaction covers projection and acknowledgement.

## Important limitations

- HTTP is plain text, **bind only to loopback**; `/stats` has no authentication. Do not expose port 8081 publicly.
- `/healthz` checks the process, not database readiness.
- HMAC has no timestamp/replay window; uniqueness of delivery IDs limits duplicate insertion, not replay of entirely new IDs.
- Request bodies are limited to 64KB; no production-grade rate limiting, TLS, logging or tracing.
- Retries currently apply to deterministic invalid-domain events. Transient DB errors propagate; a later version should add controlled retry classification, observability and fault injection.
- No performance benchmark or measured latency/throughput yet. Do not infer production scalability.
- Local test database is shared with manual runs unless you provision a separate disposable test database.
